# 隐私与数据处理

本文档说明「今日穿搭」处理哪些数据、数据去哪里、以及用户可以怎么控制。目标是让使用者和二次开发者都能一眼看清边界，而不是用「我们重视隐私」这类空话代替。

## 一句话版本

- 默认**不收集**任何遥测、埋点或统计上报。
- 衣橱、日程、打卡、设置都存在**手机本地**。
- 只有两个可选功能会联网：**云端版型识别**（上传用户主动确认的单张衣服照片）和**可选下载的本地模型**（从 HuggingFace 拉取权重文件）。天气查询会向 Open-Meteo 发送大致坐标。
- 不使用账号系统，没有服务端数据库。

## 数据存在哪里

| 数据 | 位置 | 是否离开设备 |
|---|---|---|
| 衣橱单品、打卡、日程、示例社区 | Room 数据库 `ootd_today.db`（应用私有目录） | 否 |
| 用户设置、专家名称与偏好、推送时间 | DataStore `ootd_settings` | 否 |
| API Key | DataStore，经 Android Keystore AES/GCM 加密 | 否 |
| 单品照片 | 应用私有目录 | 仅在用户确认后、使用云视觉时作为请求内容发送 |
| 动态配图 | 应用私有目录 | 否（社区为本地示例，无上传） |
| 本地模型文件 | `getExternalFilesDir()/expert_models/` | 否，仅从 HuggingFace 下载 |
| 模型下载状态 | SharedPreferences `local_models` | 否 |

Android 自动备份默认开启，但已通过 `res/xml/backup_rules.xml` 与 `res/xml/data_extraction_rules.xml` **排除模型文件与模型状态**，避免把近 1 GB 的权重备份到云端。

## 网络请求清单

| 目标 | 触发方式 | 发送内容 |
|---|---|---|
| `api.open-meteo.com` | 打开首页/日历/每日提醒 | 经纬度（保留到城市级精度即可）、日期范围 |
| 用户配置的视觉服务 | 用户点「识别版型」并**逐次确认上传** | 一张重新编码后的 JPEG（最长边 1280，无原始 EXIF）+ 固定提示词 |
| 用户配置的对话服务 | 用户主动点「请专家看看」或发送追问 | 系统提示词 + 衣橱文字信息（名称/品类/颜色/风格/版型/场合）+ 天气；若用户开启「上传照片」，还会附带最多若干张单品照片的 base64 |
| `huggingface.co`（或可选镜像） | 用户主动点下载本地模型 | 仅下载请求；不上传任何用户数据 |

视觉与对话服务由**用户自己填写**地址、模型名和 API Key。应用不内置任何服务商密钥，也不经手任何第三方账号。

## 照片处理

版型识别路径上的处理顺序：

1. 用户选择或拍摄单件衣服照片。
2. 界面明确提示将上传一张照片，用户确认后才继续。
3. 本地将图片缩放至最长边 1280，纠正 EXIF 旋转，重新编码为 JPEG —— 原始 EXIF（可能含拍摄地点、设备信息）不会离开设备。
4. 仅这张处理后的 JPEG 发送到用户配置的视觉服务。
5. 返回的版型候选必须由用户逐项确认后才写入衣橱。

不确认、不配置视觉服务时，照片只保存在本地，不会上传。

## 权限

| 权限 | 用途 |
|---|---|
| `CAMERA` | 应用内相机拍摄单品/动态配图；进入相机页时申请 |
| `ACCESS_COARSE_LOCATION` | 按城市查天气；拒绝后使用默认城市 |
| `POST_NOTIFICATIONS` | 每日穿搭提醒；仅在用户开启提醒时申请 |
| `INTERNET` | 天气、可选的视觉/对话服务、模型下载 |

定位与相机均为可选能力，拒绝不影响衣橱、推荐、日程、统计等核心功能。

## 用户控制

- 删除单品、打卡、日程：在对应页面直接删除，数据库同步移除。
- 删除本地模型：专家页提供删除入口，会同时清理下载记录。
- 清除 API Key：把设置页的 Key 输入框留空并保存。
- 卸载应用会删除本地全部数据（包括照片与数据库）。

## 第三方组件

- ML Kit 图像打标在设备本地运行，不联网。
- 云视觉/云对话是用户自行配置的第三方服务，其数据留存、训练使用、跨境传输等以该服务商的条款为准。若要在生产环境面向普通用户提供，应增加服务端代理、额度控制、隐私说明和删除路径，而不是让用户自填 Key。
- Qwen3 模型权重由 HuggingFace 分发，遵循其模型许可证（Apache-2.0）。

## 不做什么

- 不做用户画像，不接入广告 SDK，不上报崩溃日志到第三方。
- 不把人脸、体型、肤色作为分析对象；视觉提示词明确禁止分析人的身份与身体。
- 不把用户衣橱或照片当作训练数据。
- 社区功能是本地示例内容，不是真实社交网络，也不会公开展示任何用户数据。

## 已知边界

- 照片背景仍可能包含个人信息，应用无法保证背景干净；建议拍摄单件衣物并避开无关背景。
- 使用第三方云服务时，数据是否离开所在司法辖区取决于用户选择的服务商。
- 本文件描述的是当前原型的行为；若二次开发接入服务端，应同步更新本文件与 README。
